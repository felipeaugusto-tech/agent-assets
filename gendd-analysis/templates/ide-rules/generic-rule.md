# Generic IDE Rule Template

> Generated by GenDD-Flow
> This template produces `.ai-rules/` directory with a README and individual rule files for any IDE.

## About Generic Rules

This format is a portable, IDE-agnostic fallback for IDEs that do not have a specific rule format (or for new IDEs whose format is not yet known). The rules are stored as plain markdown files in an `.ai-rules/` directory, with a README explaining how to use them.

Any AI coding assistant can be pointed to this directory. The format is human-readable, so it also serves as documentation for the team.

## GenDD-Flow output format (required)

Emit one `<!-- FILE: basename.md -->` per file. Files are written under **`.ai-rules/`** at the project root. Names must be a single path segment and end in `.md` (e.g. `README.md`, `general.md`, `security.md`).

If the model response has **no** `FILE:` markers, GenDD-Flow falls back to a single `docs/ide-rules.md` (legacy) for compatibility.

```

```

| Always | When Applicable |

| Invalid input | Authentication |
| Not found | External failure |
| | Multi-tenant isolation |
| | Boundary conditions |

## Mocking

Mock: External APIs, databases (unit), file system, time
Never mock: Code under test, value objects, pure functions

## E2E Rules
- Selectors: `data-testid` only
- Waits: Explicit -- never `sleep()`
- Each test starts from clean state

## Coverage Priority
1. Critical business logic (highest)
2. Public APIs / Controllers
3. Data access
4. Utilities (lowest)
5. Generated code (skip)

### 5. .ai-rules/security.md

```markdown
# Security Rules -- {PROJECT_NAME}

These rules are NON-NEGOTIABLE. They apply to all code in this repository.

## Never Hardcode Secrets
No passwords, API keys, tokens, certificates, or private keys in source code.

## Never Log Sensitive Data
No auth credentials, payment data, PII, health information, private keys.
Mask when needed: card `****4242`, email `j***@example.com`, tokens never.

## Validate All Input
Type, format, length, range, encoding. Allowlists over denylists.

## Parameterized Queries
Never string concatenation in SQL or query building.

## Multi-Tenant Isolation
Every query includes tenant context. Server-derived, never client-supplied.

## Auth on Every Request
Verify authentication and authorization. Fail closed. Log failures.

## Safe Error Messages
Users: Friendly message. Logs: Full details. API: Error code + safe message.
Never expose: Stack traces, DB schema, file paths, internal IPs.

## Code Review Checklist
- [ ] No hardcoded secrets
- [ ] No sensitive data in logs
- [ ] All input validated
- [ ] Parameterized queries
- [ ] Auth checks present
- [ ] Tenant isolation enforced
- [ ] Safe error messages
```

## Usage Notes

- This format works with any AI assistant -- just reference the directory.
- Files are plain markdown with no special frontmatter or configuration.
- The format is also useful as human-readable documentation for the team.
- When migrating to a specific IDE format, use these files as the content source and adapt the structure to the target format.
- Keep individual files focused on one area. This makes it easy to extract and adapt content for specific IDE formats.
