# Claude Code Rule Template

> Generated by GenDD-Flow
> This template produces `CLAUDE.md`, `.claude/commands/*.md`, and optionally `.claude/skills/*/SKILL.md` for the target repository.

## About Claude Code

Claude Code reads a `CLAUDE.md` file at the project root for persistent instructions. It supports **slash commands** (`.claude/commands/{name}.md` → `/{name}`) and **project skills** (`.claude/skills/{skill-name}/SKILL.md`, with YAML frontmatter per Anthropic’s Claude Code skills documentation). Together, these give project-wide context, repeatable workflows, and reusable capabilities.

## GenDD-Flow output format (required)

Emit one HTML comment **before** each file’s content. The CLI writes only these allowed marker paths (no `../`, no extra path segments):

| Marker in model output | Written path |
|------------------------|----------------|
| `CLAUDE.md` | `./CLAUDE.md` |
| `commands/{name}.md` | `./.claude/commands/{name}.md` |
| `skills/{skill-name}/SKILL.md` | `./.claude/skills/{skill-name}/SKILL.md` |

Use **lowercase hyphenated** `{name}` and `{skill-name}` (match `[\w.-]+` only).

### Do not emit only `CLAUDE.md`

**Unless the supplied context is truly empty of workflows**, your response **must** include **multiple** `<!-- FILE: ... -->` blocks:

1. **Always** `<!-- FILE: CLAUDE.md -->` first — concise root instructions grounded in the repo + docs.
2. **Slash commands** — add **at least two** `<!-- FILE: commands/<command>.md -->` files for distinct, repeatable workflows implied by the context (e.g. `review-pr.md`, `generate-tests.md`, `check-security.md`, `run-migrations.md`). Each file must be self-contained markdown the agent runs when the user invokes `/<command>`.
3. **Skills (when applicable)** — if the documentation describes a **reusable capability** (tooling, domain procedure, multi-step agent behavior) that fits Claude Code **skills**, add `<!-- FILE: skills/<skill-name>/SKILL.md -->` with valid YAML frontmatter (`name`, `description`, and optional fields per current Anthropic docs) followed by markdown instructions. Omit skills if nothing in the context warrants a separate skill beyond commands.

If you only output `CLAUDE.md`, you have **not** met this template’s contract.

### Paths in `CLAUDE.md` (critical)

- The file you write is for **this target repository’s working tree only**.
- **Do not** list markdown links or bullets pointing at paths that **do not exist** in this repo (for example `docs/standards/...`, `docs/specs/...`, or paths copied from a **separate documentation repository** that was only pasted into the prompt). Those files are not on disk here unless they appear in the **repository snapshot** you were given.
- External or out-of-repo guidance must be **summarized inside** `CLAUDE.md`, commands, or skills—not deferred to fictional paths.
- You **may** reference `docs/context/*.md` or `docs/standards/*.md` **only** when that layout is present in the repository snapshot for this project (typical GenDD-Flow outputs). If absent, **omit** any “see also” file list or replace it with “use the slash commands in `.claude/commands/`”.

```markdown
- Never hardcode secrets, credentials, API keys, or tokens in source code

- Every database query must include tenant context
- Tenant context is derived server-side -- never trust client-supplied tenant IDs

- Naming: {TEST_NAMING_PATTERN}
```

```
## Commands

Custom workflows are available as slash commands in `.claude/commands/`.
```

### 2. .claude/commands/*.md (Slash Commands)

Each file defines a slash command that can be invoked in Claude Code. The filename becomes the command name.

**File structure:** `.claude/commands/{command-name}.md`

Each command file is a markdown document with instructions for a specific workflow. Claude Code executes the instructions when the user invokes the command.

#### Example: .claude/commands/review-pr.md

```markdown
Review the current PR for:

1. **Security**: Check for hardcoded secrets, missing input validation, SQL injection, logging sensitive data, missing auth checks, multi-tenant isolation gaps.

2. **Code Quality**: Check for naming convention violations, missing error handling, functions doing too many things, missing tests.

3. **Testing**: Verify AAA pattern, descriptive names, independence, coverage of happy path + error cases + edge cases.

4. **Patterns**: Verify consistency with existing codebase patterns. Flag deviations.

Output a structured review with:
- MUST FIX: Security issues, bugs, broken tests
- SHOULD FIX: Convention violations, missing tests, code quality
- CONSIDER: Suggestions, alternative approaches

Reference specific files and line numbers.
```

#### Example: .claude/commands/generate-tests.md

```markdown
Generate tests for the file or function I specify.

Follow these rules:
- Use the {TEST_NAMING_PATTERN} naming pattern
- Follow Arrange-Act-Assert structure
- Include scenarios: happy path, invalid input, not found, edge cases
- Add authorization and multi-tenant scenarios if the code checks permissions or accesses data
- Mock at boundaries only (external APIs, databases, file system)
- Use {TEST_FRAMEWORK} framework
- Place tests in {TEST_LOCATION}

Do not generate tests for generated code, simple getters/setters, or DTOs.
```

#### Example: .claude/commands/check-security.md

```markdown
Scan the codebase for security issues:

1. **Secrets**: Search for hardcoded passwords, API keys, tokens, connection strings
2. **Input Validation**: Find endpoints or functions that accept external input without validation
3. **SQL Injection**: Find string concatenation in database queries
4. **Logging**: Find logs that might contain sensitive data
5. **Auth**: Find endpoints missing authentication or authorization checks
6. **Multi-Tenant**: Find database queries missing tenant context
7. **Dependencies**: Check for known vulnerabilities in dependencies

Report findings grouped by severity (Critical, High, Medium, Low) with file paths and line numbers.
```

## Usage Notes

- `CLAUDE.md` should stay concise. Reference context area files for detailed guidance rather than duplicating content.
- Slash commands are self-contained -- each file should include all the context needed to execute the workflow.
- Claude Code respects `CLAUDE.md` files in subdirectories for monorepo setups. A `packages/api/CLAUDE.md` would apply when working in that directory.
- Keep `CLAUDE.md` under 500 lines. If it grows beyond that, extract details into context area files and reference them.
