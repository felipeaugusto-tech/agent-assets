# GitHub Copilot Instructions Template

> Generated by GenDD-Flow

## About GitHub Copilot Instructions

GitHub Copilot reads a single instruction file at `.github/copilot-instructions.md`. All rules go in this one file, organized by section headers. Copilot uses these instructions to guide code generation, completions, and chat responses.

Unlike Cursor (multiple files with globs) or Claude Code (root file + commands), Copilot uses a **single** repository instruction file. Keep it well-organized with clear section headers.

## GenDD-Flow output format (required)

GitHub loads **one** file: `.github/copilot-instructions.md`. In GenDD-Flow, use only this marker. You may repeat `<!-- FILE: copilot-instructions.md -->` for each major section; the CLI **merges** all blocks in order into that single file.

```markdown
<!-- FILE: copilot-instructions.md -->
# {PROJECT_NAME} -- Copilot Instructions
## Project Identity
...

<!-- FILE: copilot-instructions.md -->
## Security
...
```

## Security Rules (Non-Negotiable)

### Never Hardcode Secrets
No passwords, API keys, tokens, certificates, or private keys in source code.
Use environment variables, secret management systems, or config files excluded from version control.

### Never Log Sensitive Data
- Authentication: Passwords, API keys, tokens, session IDs, JWTs
- Payment: Credit card numbers, CVV, bank accounts
- Personal: SSN, driver's license, passport numbers
- Health: Medical records, diagnoses
- Contact: Email + name combinations, addresses

When referencing sensitive data in logs, mask it:
- Credit card: `****4242`
- Email: `j***@example.com`
- Token: Never log -- use request ID

### Validate All Input
Never trust external input (user input, APIs, files, URLs, environment).
Validate type, format, length, range, encoding.
Use parameterized queries -- never string concatenation in SQL.

### Multi-Tenant Data Isolation
- Every database query includes tenant context
- Tenant context derived server-side, never from client
- Cross-tenant access must be architecturally impossible
- Tenant model: {TENANT_MODEL}

### Authentication & Authorization
- Verify auth on every request -- do not cache auth decisions
- Use standard protocols (OAuth2, OIDC, JWT with proper validation)
- Check authorization before every action -- fail closed
- Log authorization failures

### Secure Error Handling
- End users: Friendly message, action to take -- never stack traces
- Logs: Full details, stack trace, context -- never sensitive data
- API responses: Error code, safe message -- never DB schema or internal paths

## Usage Notes

- Copilot reads this file automatically -- no additional configuration needed.
- Keep the file well-structured with clear markdown headers. Copilot uses section headers for context relevance.
- Since everything is in one file, prioritize the most important rules at the top.
- Avoid exceeding ~1000 lines. If the file grows too large, focus on the highest-impact rules and reference external documentation for details.
- Unlike Cursor, there is no glob-based rule activation. All rules are always available to Copilot.
- Test by asking Copilot questions about your project conventions in chat -- it should reference these instructions.
