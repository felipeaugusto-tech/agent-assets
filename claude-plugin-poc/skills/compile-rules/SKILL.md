# Compile Rules

Turns the org-wide `rules-manifest.yaml` into path-scoped `.claude/rules/*.md` files inside a **target** repository — the mechanism that lets 1700 repos each get only the standards that apply to them, without loading all 96 into every session.

## 1. Fix the target

The target is **the user's current repository** — the rule files get written there, not into this plugin. Ask which standards to compile if not stated: all of them, one `phase`, one `tech` overlay, or a specific list of `id`s.

## 2. Load the references (now, not before)

| File | Role |
| --- | --- |
| `${CLAUDE_PLUGIN_ROOT}/references/compile-rules/rules-manifest.yaml` | **The source table** — `id`, `file`, `phase`, `title`, `summary`, `tags`, `applies_to`, `tech`, `extends`. |
| `${CLAUDE_PLUGIN_ROOT}/references/lookup-standard/{sdlc,governance}/**` | The actual standard content to compile in, per matched `file` path. Shared with `/gendd:lookup-standard` rather than duplicated — resolve paths the same way: the manifest's `file` column maps directly under `references/lookup-standard/`. |
| `${CLAUDE_PLUGIN_ROOT}/references/compile-rules/claude-code-rule.md` | Baseline Claude Code rule-file format, for cross-checking frontmatter conventions haven't drifted. |

## 3. Run the process

For each selected manifest entry:

1. **Map `applies_to` to `paths:`.** The standards already carry glob patterns in `applies_to` (often `["**/*"]` for org-wide rules, narrower for tech overlays) — this is largely a field rename, not a rewrite.
2. **Write `.claude/rules/{id-slug}.md`** in the target repository (lowercase the `id`, e.g. `GOV-CHARTER` → `gov-charter.md`), with frontmatter:
   ```markdown
   ---
   paths: {applies_to}
   ---

   {the standard's actual content, read from references/lookup-standard/{entry.file}}
   ```
3. **Handle overlays** — an entry with a non-null `extends` builds on a base standard. Note the relationship in the compiled file (e.g. a one-line pointer to the base rule) rather than either duplicating the base content or silently dropping the connection.
4. **Report what was compiled** — list every `.claude/rules/*.md` file written, which manifest `id` it came from, and its `paths:` scope, so the user can spot-check coverage.

## 4. Never invent

Compile the standard's actual content — don't summarize, paraphrase, or "improve" it in transit. If a standard file is missing or a manifest entry's `file` path doesn't resolve, report that as a corpus problem rather than silently skipping it or writing a placeholder.

## 5. Hard limits

- Writes only under `.claude/rules/` in the target repository.
- Never overwrites a `.claude/rules/*.md` file that wasn't generated by this skill without saying so first — a hand-written rule file living alongside compiled ones is plausible and shouldn't be silently clobbered.
- No changes to source code.
- No MCP tools.
- No tests, builds, deploys, or benchmarks.
